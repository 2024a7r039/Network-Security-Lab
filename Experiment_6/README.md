# Lab 06: Secure Remote Administration Using OpenSSH

**Subject:** COM-511 Network Security Laboratory  
**Focus Areas:** SSH Transport Security, Host Fingerprinting, and Ed25519 Key-Based Access  

---

## 1. Lab Objective
This repository documents the practical setup and verification of secure remote login using the OpenSSH suite. The lab demonstrates how to configure an OpenSSH daemon (`sshd`) on a Kali Linux virtual machine, validate host identity from a Windows workstation to prevent interception attacks, and replace interactive password logins with cryptographic Ed25519 public-key authentication.

---

## 2. Theoretical Background
Secure Shell (SSH) secures remote administration across untrusted networks by providing three core security guarantees over TCP port 22:
- **Confidentiality:** Encrypts all terminal commands and output across the session.
- **Integrity:** Uses cryptographic message authentication codes to detect packet tampering in transit.
- **Authentication:** Enforces mutual verification through a two-stage identity check:
  1. **Host Verification (Transport Layer):** The client validates the server's public host key fingerprint before trusting the connection, recording verified keys inside the local `known_hosts` file.
  2. **Account Verification (User Authentication Layer):** The user proves access rights via an account password or a cryptographic signature generated by a local private key (`id_ed25519`) verified against the server's `~/.ssh/authorized_keys` file.

## 3. System Topology & Specifications
* **Client Workstation:** Windows 10/11 running native OpenSSH Client
* **Remote Target Host:** Kali Linux VM running OpenSSH Server (`sshd`)
* **Network Service Port:** TCP/22
* **Asymmetric Key Type:** Ed25519 (`ssh-ed25519`)
* **Authorization Scope:** Local virtualized laboratory network

## 4. Execution Walkthrough

### Stage A: Verifying Client and Server Environments
1. **Check OpenSSH Client Version on Windows:**
   ```cmd
   ssh -V
   ```
2. **Provision and Enable OpenSSH Server on Kali Linux:**
   ```bash
   sudo apt update
   sudo apt install -y openssh-server
   sudo systemctl enable --now ssh
   ```
3. **Validate Daemon State and Active TCP Socket:**
   ```bash
   systemctl status ssh --no-pager
   sudo ss -tlnp | grep ':22'
   ```
4. **Retrieve Server Account and Network Address:**
   ```bash
   whoami
   hostname
   hostname -I
   ```

### Stage B: Host Key Verification and Password Session
1. **Extract the Server's Ed25519 Host Fingerprint on Kali:**
   ```bash
   sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```
2. **Open the Initial SSH Connection from Windows:**
   ```powershell
   ssh <username>@<server_ip>
   ```
3. **Establish Host Trust:**
   Compare the `SHA256` fingerprint displayed by the client prompt with the fingerprint retrieved directly on the Kali console. Once confirmed, enter `yes` to register the key in `known_hosts` and input the account password.
4. **Confirm Remote Shell Execution:**
   ```bash
   whoami
   hostname
   pwd
   exit
   ```

### Stage C: Generating and Installing Ed25519 Keys
1. **Create a Client Ed25519 Key Pair on Windows:**
   ```powershell
   ssh-keygen -t ed25519 -C "student@lab"
   ```
2. **View the Generated Public Key Fingerprint:**
   ```powershell
   ssh-keygen -lf $HOME\.ssh\id_ed25519.pub
   ```
3. **Authorize the Public Key on the Remote Kali Account:**
   Append the `.pub` file contents to the server's `~/.ssh/authorized_keys` file and enforce strict directory/file permissions:
   ```powershell
   type $HOME\.ssh\id_ed25519.pub | ssh <username>@<server_ip> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
   ```
   *(Note: Only the `.pub` public key is transferred; the private key never leaves the Windows client).*

### Stage D: Validating Key-Only Login
1. **Test SSH Login with Password Authentication Disabled:**
   ```powershell
   ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no <username>@<server_ip>
   ```
2. **Verify Remote Session Context and Disconnect:**
   ```bash
   whoami
   hostname
   exit
   ```

## 5. Common Faults & Diagnostic Guide
* **Service Not Listening (`Connection refused`):** Confirm `sshd` is active via `systemctl status ssh` and check socket bindings with `sudo ss -tlnp | grep ':22'`.
* **Network Unreachable (`Connection timeout`):** Verify the VM IP address (`hostname -I`) and confirm that the hypervisor network adapter allows host-to-VM traffic.
* **Public Key Rejected (`Permission denied`):** Inspect client debug output using `ssh -vv <username>@<server_ip>` and verify that `~/.ssh` (`700`) and `~/.ssh/authorized_keys` (`600`) on Kali are not writable by group or others.
* **Server Logs Inspection:** Monitor real-time authentication events on Kali using `sudo journalctl -fu ssh.service`.
